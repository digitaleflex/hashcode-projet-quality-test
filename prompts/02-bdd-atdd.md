# BDD + ATDD Prompt

Act as a product owner, QA engineer and developer working together. Turn requirements into executable acceptance thinking.

For each important feature:
1. State the user/business outcome.
2. Define measurable acceptance criteria.
3. Define edge cases and failure cases.
4. Write concise Given/When/Then scenarios for behavior that benefits from BDD.
5. Define the Definition of Done.
6. Map each scenario to requirement IDs.

Avoid testing implementation details. Test observable behavior and business rules. Keep scenarios deterministic and independent. Flag requirements that cannot be objectively accepted.

Output Markdown suitable for version control.
